| Roadmap area | Evidence in this checkpoint |
| --- | --- |

| APP-RESPONSE / APP-STDIO-WRITER | Fixed draft storage, copied temporary metadata/body, repeated Set-Cookie, header validation, exact/overflow JSON, serializer invoked once, rollback, tiny fallback, HEAD/bodyless response rules and eligible borrows. Depth-128 state-changing requests execute once across arena drains, with real batches larger than one. |
| APP-COMPOSITION | Independent App instances/state/ports/stop flags, frozen/transactional registration, startup budgeting, raw captures, static precedence in both registration orders, explicit HEAD and extension methods, 404/405/Allow/OPTIONS. Native examples additionally exercise bound endpoints, typed wrappers and synchronized worker CRUD. |
| APP-FORM / APP-STDIO-READER | Media/encoding checks before segmented-copy fallback, logical payload readers/copies excluding framing/trailers, independent query/form fields, explicit decoding, limits and ordinary malformed-data errors. |
| APP-MULTIPART | Validates complete body before exposing parts; repeated fields/files, missing/empty filename, binary/empty payload, quoted metadata, truncation, first closing delimiter, near-boundaries and limits. A wire fixture places every body byte in its own HTTP chunk and then copies explicitly. Invalid terminal syntax does not apply upload side effects. |

These are the first implemented API-01–05 contracts and scoped witnesses.
API-06's public middleware/locals/cookie API and API-07's typed resumable endpoints
remain queued. The complete APP-NATIVE successor gate is not claimed. Broader
combined-limit/failure-injection schedules, App-specific multi-shard execution
qualification, dynamic leases/offload, receive streaming and inherited engine
production/deployment qualification remain outside this receipt. Generic service
libraries can allocate/block; the framework's sealed allocator does not intercept
their behavior, and HTTP cancellation does not automatically cancel std.Io calls.

One-shot generated/copied bodies compact once within the output arena before
publication; `response_draft_copy_bytes` accounts for that copy. The reservation
is App-wide. Neither zero-copy for all responses nor zero API overhead is claimed.
