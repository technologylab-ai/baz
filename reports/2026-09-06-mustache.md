# Mustache integration — 6 September 2026

Baz adds startup-owned Mustache templates, explicit cached partials, and typed
rendering into reserved HTML response storage. The new greeting-page example is
53 lines of Zig, with separate HTML/CSS assets. This is a correctness and ownership
gate; no performance comparison was run or changed.

## Browser and ownership checks

The rendered example passed five checks in Chrome 152.0.7977.76 on macOS arm64:
desktop, 390/320-pixel layouts, actual form submission and escaping, two user
cards, linked engine footer, and no horizontal overflow or unexpected network
resources. Screenshots were inspected. The [browser receipt](2026-09-06-mustache/local/example-browser.json)
and [terminal server statistics](2026-09-06-mustache/local/example-browser-server-stats.json)
are retained. The Baz landing page and source/document reader also passed all
17 browser groups with 22 examples and 71 documents, including the rendered
Mustache preview and its source link.

Mac builds, HTTP suites, and browser checks held the cooperative host reservation.
Owned process groups stopped before release. All Mustache wire/browser server
receipts have zero terminal live connections and operations, and zero framework
allocation calls after start. The template's separate, fixed startup allocation
is application-owned and is **not** included in the engine's heap ledger.

Rendering produces bytes directly into the private reserved response draft.
There is no allocated rendered string or scratch-to-body copy. Final publication
still compacts the draft once, with existing copy accounting. This is not a
kernel zero-copy claim. Failed one-shot rendering publishes no partial success;
standalone writer rendering may leave a prefix. See [the API and limits](../docs/MUSTACHE.md).

Lambdas, inheritance/blocks, dynamic partial names, implicit filesystem lookup,
TLS, and an owned std.Io provider are outside this slice. Framework bounds do
not isolate arbitrary application code. Baz remains experimental.
