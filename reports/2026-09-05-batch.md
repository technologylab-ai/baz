# Bounded response batching — 2026-09-05

Batching ordinary handler responses raised the same binary's pipeline-16 median
from **233,768 to 1,220,510 responses/s (5.22×)**. A separate one-core comparison
measured **1,833,059 for Zig versus 2,617,684 for libreactor**. Assertions remain
enabled, callbacks still run for every request, and all output cells are reserved
at startup. This closes much of the original gap; it does not establish parity,
production capacity or reliable request tails.

## Architecture and ownership

Default inline/zero-worker execution and gathered header/body output remain.
Config.response_batch_limit is 1–16, default16; worker mode reserves one cell.
Each inline connection owns startup output/header/chunk cells. The common
request/writer callback freezes a finished cell, advances the input cursor and
can handle the next already-buffered request without waiting for a send. Input
bytes remain immutable while any response borrows them. This supports generated
output and distinct borrowed request bodies, without a plaintext cache.

At most 80 framing/payload spans feed stable startup iovecs/msghdr storage;
Linux submits SENDMSG through io_uring and macOS uses nonblocking sendmsg/kqueue.
Aggregate send_chunk/i32 limits and cross-span partial completion remain.
Drain at cell exhaustion, end of available input, flush/close or exhausted
callback budget. Never wait to fill a batch. Flush is a barrier: drain all
preceding cells and the active snapshot, then resume that same request/state
with empty output storage. Compact any suffix once only after all borrows end.

A global64 callback budget, at most the effective batch limit per connection,
and rotating scan start bound dispatch work. Oldest-unsent deadlines remain;
checks surround application invocation, but a violating callback cannot be
preempted. A parser error or Connection: close response drains valid preceding
output. Handler `.close`, invalid output or timeout can discard earlier unsent
cells. `finish()` returning does not promise a completed send.

Completed counts and request-cycle maxima are recorded at whole-batch drain.
A successfully sent prefix of a subsequently canceled batch may be omitted.
These are conservative completion observations, not individual latency events.
Config.heapBytes includes exact requested framework allocations, cells and gather
metadata; requested worker stacks are separate. Kernel/libc/pthread/app memory,
allocator overhead and RSS remain outside that bound. Ordinary kernel socket
copies remain; this is not SEND_ZC or NIC zero-copy.

## Correctness evidence and limits

At b7ac355, macOS M3 Max arm64, macOS26.6.2 build25G83, exact Zig0.16.0:
Debug and ReleaseSafe each passed 14/14 build steps,52/52 unit executions,
26 generic,10 inline,11 gather and15 batch cases. Linux ReleaseSafe passed the
same52+62 cases. The 32-distinct-generated-response fixture reduced sends32→2
and compaction25,251→816bytes. Distinct borrowed POST bodies survived23-byte
submissions. Mixed routes, limits1/2/4/16, one-byte sends, order barriers,
128 empty flush resumptions and3,585-response fairness fixtures passed.
These are bounded witnesses, not starvation or latency guarantees.

Review found that the original 2MiB-body cancel fixture could drain earlier
responses before that body completed. It did not witness several frozen cells
at cancellation. Checkpoint5620905 therefore adds a separate depth16 pipeline
of complete requests for a startup-loaded65,535-byte asset, tiny socket buffers,
a1s server deadline and finite process/client watchdogs. Its counter observes
retained cells when pending gather cancellation is successfully requested;
a target may still race normal completion. Exact65536-byte input initially
failed StreamTooLong because Zig's readFileAlloc limit is exclusive; the final
fixture and documentation retain the65,535-byte boundary.

Mac ReleaseSafe's16-case batch suite witnessed16 retained cells,80 short send
completions, one pending cancel and one canceled target terminal, then zero
owners/late allocations. Linux's separate witness retained16 cells, observed two short send completions
and one pending cancellation request; the target completed normally in the race,
so its canceled-target counter was zero. Both target and cancel owners drained.
At5620905, both native hosts passed52 Debug and52 ReleaseSafe unit executions,
26 generic +10 inline +11 gather +16 batch cases and30,000 exact-body ReleaseSafe
smoke responses. Native packet files accompany this report. A cancellation acknowledgement alone never frees target storage.
